Design paper · October 2026

Engram: memory for AI agents that knows what matters

A salience-gated, activation-weighted memory architecture for personal AI agents, with an audit of a deployed system, a mathematically grounded visualisation, and a conversational interface to memory itself.

Abstract

Personal AI agents need long-term memory: who the people in a user's life are, what was promised to whom, how the user likes things done. Current agent memory systems are good at storing and retrieving facts. They are weak at deciding which facts deserve storing in the first place. They also treat a fact learned once a year ago the same as one used every day.

We audited a deployed memory system that already does several things well. It verifies every stored fact against the source text, ranks sources by trust, and keeps a timeline of when each fact was true. It has no model of importance. Of 662 logged conversation turns it stored 8 facts, 2 of which were test messages, while a user's ongoing course deadlines were missed. Facts never strengthened with use or faded with disuse, and nothing linked one person or project to another.

Engram adds four mechanisms on top of a verified, time-aware fact store. (1) A salience gate estimates the probability that a candidate memory will be needed later, and routes it to one of three outcomes: keep, hold tentatively, or skip. (2) Activation, from the ACT-R model of human memory, gives each fact a strength that rises with use and decays as a power law of time. (3) An association graph links entities by how much more often they co-occur than chance (PPMI). Recall spreads activation across it with Personalized PageRank. (4) A memory agent lets the user talk to their memory directly; it asks only the questions whose answers reduce its uncertainty most, and those answers train the gate. Every visual property of the proposed memory visualisation is one of these computed quantities.

1. Introduction

Memory fails in two directions. It fills with trivia ("set a two-minute timer"), or it misses the thing that mattered ("my project deadline is Friday"). One mechanism should handle both.

An agent that stores everything carries irrelevant facts into every prompt. That costs tokens and distracts the model. An agent that stores too little forgets what the user told it last week and feels like a stranger. People solve this with attention and consolidation. Most of a day is never encoded at all. What surprises us, what we act on, and what we come back to gets stabilised, and what we never revisit fades.

Most agent memory systems handle this with a single instruction to the language model, such as "skip small talk". That instruction can't be measured, tuned, or explained. This paper replaces it with explicit quantities that can be computed, inspected and fitted to data.

Contributions.

  • An audit of a deployed agent memory, with a list of failure modes that recur across systems of this kind (§4).

2. Background: how agent memory works

A language model forgets everything between conversations. "Memory" for an agent is an external store plus two processes around it:

  • Writing. After a conversation, a model reads what was said and pulls out facts worth keeping: "Priya works at Freshworks", "the user promised Dev a review by Monday". These are compared with what is already stored. Each one is added, used to update an old fact, or dropped as a repeat.
  • Reading. Before the agent answers, the system searches the store for facts related to the current message and puts the best ones into the prompt. Search is usually a mix of meaning (vector similarity of text embeddings) and exact words.

Systems differ in what they store. Some keep plain text notes. Others keep a knowledge graph: entities (people, organisations, projects) and the relationships between them. Well-built systems also keep the raw conversation, the episodes, so facts can be re-derived later. The best ones are bi-temporal: each fact records when it was true in the world and when the system learned it. That way "Meera works at Zomato" can be closed, not deleted, when she moves to Swiggy.

Two questions are left open by most designs, and they are the subject of this paper. What deserves to be written? And how strongly should each stored thing compete for a place in the prompt?

Cognitive science supplies the rest:

  • ACT-R base-level learning [13, 14] gives each memory a strength from how often and how recently it was used. Its premise is that memory strength tracks the probability a memory will be needed.
  • Synaptic tagging and capture [15] explains how a weak trace survives when something important touches it soon after. This is the model for the tentative tier.
  • Emotional arousal modulates consolidation [16]. Things that matter to us are remembered better, which motivates an importance feature.
  • Spreading activation [17] says recalling one concept primes the ones linked to it.
  • Complementary learning systems [18] pair a fast episodic store with a slow structured one. That is the shape of the whole design.

4. Case study: auditing a deployed memory

The baseline is the memory of a personal-assistant app in which several AI agents work for one user and share one memory of that user's world. The agents chat, take phone calls on the user's behalf, read email, and run tasks on the user's phone. Its memory has four layers:

  1. Episodes: every chat turn, call line and app result, stored verbatim.
  2. Entities: people, organisations, projects and places, with every name, phone number and email seen for them.
  3. Facts: one-sentence statements about an entity, each with dates, a trust level and the exact quote it came from.
  4. Profiles: a short summary per entity, rebuilt when its facts change.

After a conversation has been quiet for 90 seconds, one model call extracts entities and facts from it. The server then checks every result before storing it. We read the memory module, every component that reads from it, and its evaluation suite, then queried the production database.

662episodes logged over four days
8facts stored (1.2% yield)
2 / 8stored facts that are test noise
57%of episodes are the agents' own replies

A low yield isn't wrong in itself, since much of this history is the user trying out features ("Hey there", "Start a 2 minute timer"). The problem is what got through and what didn't. Stored: "[A contact] was sent an SMS … saying: Test from [the app], please ignore." Not stored: the user asking "Can you see the deadlines I set for MLP and MLP project?", which names two courses they are taking. The extractor has one instruction about importance and no way to weigh it.

What the baseline does well

  • Raw history is never edited. Any later, better extractor can re-read it. This is the same episode layer Zep uses [3].
  • Evidence is verified. The server drops any fact whose quote isn't found word for word in its source. This is stricter than the published pipelines of Mem0 or Zep, and it is why the system resists poisoning (instructions hidden in an email can't become memories).
  • Sources are ranked by trust. The user outranks the agents, who outrank outside content such as emails, web pages, callers and app results. Outside content can't set the user's preferences or override better-trusted facts.
  • Facts are bi-temporal. When a fact stops being true it is closed with an end date. When the user says a fact is wrong it is retracted permanently.
  • Evaluations come first. A suite of 13 scenarios in the style of LongMemEval [9]: changed jobs, one person under several names, poisoned emails, corrections, and more. The system scores 18/18 questions, against 14–15 for the note-based memory it replaced.

5. Architecture

5.1 What is stored

The four layers stay: episodes → entities → facts → profiles. Each fact gains four fields:

  • importance: how much it matters, rated when it is extracted;
  • salience: the gate's probability that it will be needed (§5.2);
  • uses: the times it was learned, restated or recalled on request (§5.4);
  • mentions: every entity the sentence names, not just its subject (§5.5).

A new kind of entity, the period, holds chapters of a life: "the online degree", "building the startup", "the year in Bangalore". This follows the Self-Memory System model of autobiographical memory [19]. Lifetime periods contain general events, which contain specific moments, and people naturally recall in that order. Edges between entities are not stored. They are computed from mentions, so they can never drift out of sync with the facts.

5.2 Writing: the salience gate

The gate has three stages. Only the middle one uses a language model, and it is the same single call the baseline already makes.

Stage 0: a free pre-filter. Some episodes can't hold a lasting fact. These include greetings and acknowledgements with no names, numbers or dates; device commands such as alarms, timers or the flashlight; and an agent's reply that adds no name, number or date beyond what the user said. These are skipped before any model call. They stay in the episode log, so nothing is lost: a better extractor can always re-read them.

Stage 1: extraction with ratings. For each candidate fact, the model also answers two multiple-choice questions. Language models give more consistent answers on a fixed scale than when asked for a free number.

  • Importance: trivial, minor, useful, important, or critical (scored 0.1 to 0.9).
  • Durability, meaning how long it will stay true: hours, days, months, or years (0 to 1).

Stage 2: the gate. On the server, with no model, those ratings are combined with signals the system measures itself into one probability that the fact will be needed later:

p=σ(β0+βimpi+βduru+βnovν+βtrτ+βexe+βrepln(1+r))(1)

σ is the logistic function, which turns any score into a probability between 0 and 1. The inputs:

  • i: importance and u: durability, from stage 1.
  • τ: trust of the source, from 0 (outside content) to 1 (the user).
  • e: 1 if the user explicitly asked to remember it, or said it to the memory agent (§7).
  • r: how many earlier episodes said the same thing. Repetition is evidence of importance.
  • ν: novelty, a cheap stand-in for surprise [7, 8, 20]:
ν=1−maxf∈Fscos(e,ef)(2)

Here e is the new fact's embedding (a vector representing its meaning), and Fs is everything already known about the same subject. A fact that adds nothing has ν near 0; a fact about a new subject has ν = 1.

Where the thresholds come from. If p is calibrated (§8), decision theory gives the cut-off directly. Assume missing an important fact costs three times as much as storing a trivial one. The expected cost is lowest when the system keeps anything above

θlo=cFPcFP+cFN=11+3=0.25(3)

cFP is the cost of a false keep and cFN the cost of a miss. Between 0.25 and θhi = 0.5 (the point where a fact is more likely needed than not), a fact is tentative. It is stored but not relied on:

  • it appears in recall only when strongly matched;
  • it is drawn faintly in the visualisation;
  • it fades unless something reinforces it.

This is how the design avoids both failure modes at once. Uncertain items are neither thrown away nor allowed to clutter every prompt.

Fitting the weights. The β weights start from hand-set values, then are fitted by logistic regression on labelled examples. Labels come from three places: hand-labelled real history (§8), the memory agent's questions (§7), and the user's own actions ("that's wrong" and "not important" are labels too). With seven weights, roughly 70–100 labels give a stable fit (a common rule of thumb is ten examples per weight). The fit is checked for calibration before it replaces the old weights.

5.3 Tentative memories and consolidation

A tentative fact is like a synaptic tag [15]: a weak trace that something stronger can capture later.

  • Promotion. When a later conversation restates or extends a tentative fact, its repetition count r rises, p is recomputed, and it may become long-term.
  • Capture. When an important fact about the same entity arrives soon after, the tentative one gets a smaller boost.
  • Fading. When its strength (§5.4) drops below the recall threshold with nothing reinforcing it, it is marked faded. Faded facts are hidden from recall but never deleted. The memory agent can still ask about them, and the user can still find them.

Entity summaries follow Generative Agents' reflection rule [1]. A summary is rewritten when the summed salience of its changed facts crosses a threshold, not after every change. That means fewer model calls and better summaries.

5.4 Strength: rises with use, fades with time

Every fact keeps a short list of the times it was learned, restated, or recalled on request. Its strength is ACT-R's base-level activation [13, 14]:

Bi(t)=ln∑j(t−tj)−d,d=0.5(4)

Each past use tj contributes a term that shrinks as a power of the time since then. Time is measured in days, with a floor of one hour. d = 0.5 is ACT-R's standard decay. Anderson and Schooler showed that this power law matches how likely information is to be needed again in real environments such as email and news [13]. The probability that a fact can be recalled is then:

Pi=11+e−(Ai−τ)/s,Ai=Bi+γ·logit(pi)(5)

τ is the recall threshold and s controls how sharp the cut-off is. Adding the gate's p (as log-odds, weight γ) means an important fact starts stronger.

Feedback guard. Facts placed in a prompt automatically are not counted as uses. If they were, whatever is already strong would be shown more, used more, and grow stronger still: a rich-get-richer loop. Only explicit recall requests by an agent and restatements by people count as use.

What never fades. Identity facts (a name, a phone number, a relationship) and open commitments keep full strength whatever their activation. Forgetting changes how prominent a fact is, never whether it is on record.

5.5 Reading: recall by association

Edges. Two entities are linked by how much more often they appear together than chance would predict. This is positive pointwise mutual information (PPMI) over episodes [21]. It is a statistical form of Hebb's rule, "cells that fire together wire together" [22]:

wab=max(0,lnnabNnanb)(6)

na is the number of episodes mentioning a, nab the number mentioning both, and N the total number of episodes. One consequence is worth noting. The user appears in nearly every episode, so their PPMI with everyone is about zero. Mathematically, the user is the context, not a node: the visualisation draws them as the field everything sits in, not as a hub wired to everything.

Spreading activation. The entities the current message mentions become the starting points s. Activation then spreads by Personalized PageRank [6, 23]:

π(k+1)=αs+(1−α)Wπ(k)(7)

In words: at each step, 85% of every entity's activation flows to its neighbours, split in proportion to link strength (the matrix W). The other 15% (α) returns to the starting points, which keeps recall anchored to the question. After twenty steps the error is below 0.8520 ≈ 4%. The computation is a few lines over a sparse table and needs no numerical library. A question about "the demo" then reaches the person who asked for it and the project it is for, even when neither is named.

Ranking. Each candidate fact gets one score from three parts:

Ri=wssimi+wgmaxa∈mentions(i)πa+waPi(8)
  • sim: semantic similarity to the message;
  • π: the association reached through the graph, taking the best of the entities the fact mentions;
  • P: the fact's strength from §5.4.

The weights start at 0.5 / 0.25 / 0.25 and are tuned by grid search on the evaluation questions. The brief for the prompt is then filled one whole fact at a time in score order until the budget runs out, so nothing is cut mid-sentence.

5.6 Scopes: who may hear what

The same memory serves several audiences, and they shouldn't all get the same thing.

  • The user's own agents get the full ranked brief.
  • An assistant speaking to an outside person on the phone gets the caller scope: facts about that person or naming them, nothing flagged sensitive, nothing no longer true, and no open-ended search.

The restriction is enforced in the query that reads memory, not in the prompt. A prompt can be talked around; a query can't.

7. Talking to memory

The memory agent is a conversation, by text or voice, in which the user speaks to their memory directly. They can tell it about their life, work and the people around them. It shows what it believes and where each belief came from, accepts corrections, and occasionally asks something.

  • The user's words are evidence. Everything said to the memory agent is logged as an episode at the highest trust level, with e = 1 in eq. (1). Deliberately telling memory something is the strongest signal of importance there is. It still goes through extraction and quote verification, so the agent can't invent memories, even when it's the one talking.
  • Tools:
    • recall, and a timeline by person or by life period;
    • "why do you believe this?", which returns the evidence quotes;
    • correct, retract, and "not important" (a negative label);
    • merge two entries that are the same person;
    • propose a fact, which is written only after the user confirms it.
  • A curiosity queue. The agent asks the questions it would learn the most from. Candidates are:
    • tentative facts near the threshold;
    • two current facts that disagree;
    • often-mentioned people with thin profiles;
    • promises past their due date.
    Uncertain facts are ranked by uncertainty sampling [29], using binary entropy weighted by importance:
q=H(p)·i,H(p)=−plog2p−(1−p)log2(1−p)(10)

H(p) is how uncertain the gate is, in bits. A fact at p = 0.5 is the one the system knows least about (H = 1 bit), and one at p = 0.99 needs no question (H ≈ 0.08).

Limits on asking. The agent asks at most two questions per conversation, only in its own conversation, and never the same thing twice within two weeks. A skipped question counts as a weak "not important".

Every answer is a training example for the gate's weights, so the gate learns this user's sense of what matters. This is active learning. It is also what makes the agent feel curious rather than nosy: it asks only where the answer would change something.

Voice works the same way. A real-time voice model gets the same memory tools, and the conversation becomes episodes when it ends, as phone-call transcripts already do.

8. Evaluation

Write precision and recall
On about 150 real episodes, hand-labelled keep / tentative / skip. Target: no important item skipped (recall ≥ 0.95 on items labelled keep), and under 10% noise among long-term facts. The baseline: 25% noise (2 of 8 facts) and at least 2 clear misses.
Calibration
Expected calibration error (ECE): the gap between the gate's stated probabilities and how often they turn out right, which must be under 0.1. Without calibration, the thresholds in eq. (3) have no meaning.
Answer accuracy
The existing scenario suite must stay at 18/18. New scenarios cover three cases:
  • Multi-step association: "who asked for the thing the demo is about?"
  • Fading: an old trivial fact must not outrank a recent important one.
  • Caller scope: a caller asks about an unrelated private fact and gets nothing.
Cost
Model calls per day must fall: the stage 0 filter skips most of the agents' own text. The gate, activation, PageRank and layout use no model at all, and neither does choosing questions. Only the conversation itself does.

10. Limits

  • Novelty from embeddings is a proxy, not true Bayesian surprise. A hosted model API doesn't expose the model's own probabilities for this.
  • The gate is only as good as its labels. Until there are about 100, it runs on its starting weights and should be read as a sensible default, not as calibrated.
  • PPMI is noisy for rare entities: a single co-occurrence between two rarely seen entities looks strong. An edge is drawn only when the pair co-occurs at least twice.
  • Stress majorization costs O(n²) per step. That is fine on a phone up to a few hundred entities. Beyond that, sparse stress [25] or a subset of landmark nodes is needed.

Plain-language glossary

Episode
One thing that happened, word for word: a message, a line from a call, an email an agent read.
Entity
A person, company, project, place or life chapter that memory knows about.
Fact
One sentence about an entity, with when it was true and the exact words it came from.
Embedding
A list of numbers representing a text's meaning. Texts with similar meanings get nearby numbers.
Bi-temporal
Two clocks per fact: when it was true in the world, and when the system learned it.
Salience gate
The bouncer at memory's door. It estimates how likely the user is to need something later.
Tentative
On probation: kept quietly, promoted if it comes up again, faded if it doesn't.
Activation
How "warm" a memory is right now. Use makes it warmer, and time cools it slowly.
PPMI
How much more often two things come up together than chance would predict.
Spreading activation / PageRank
Recall that follows associations, the way thinking of one person brings up the project you share.
Stress majorization
A way to place dots so that the distance between them on screen matches how related they are.
Modularity / Louvain
A way to find groups that are more connected inside than to each other: the "regions" of memory.
Calibration
When the system says 70%, it is right about 70% of the time.
Active learning
Asking the questions whose answers teach the most, instead of asking everything.
