Tubelight · design paper · 18 October 2026

Engram: a memory that knows what matters

Memory v3 for Tubelight, the successor to Memory v2 (agent-service/app/mem.py). Written after an audit of the code and of the live memory on the home server.

Abstract

Tubelight's Memory v2 is careful about truth. Every fact quotes its evidence, outside content can't give orders, and changed facts are closed rather than overwritten. It has no model of importance. The live store holds 8 facts from 662 episodes. Two of those 8 are test noise. Meanwhile, the user's coursework deadlines, which they mentioned in chat, were never stored. Facts never strengthen with use or fade with disuse. There are no links between entities, so memory can't be drawn as a graph or searched by association.

Engram adds three things on top of v2's verified core. The first is a salience gate: a calibrated probability that a candidate memory will be needed later, with three outcomes (keep, hold tentatively, skip). The second is activation: each fact gets a strength from the ACT-R memory equations that rises with use and fades as a power law of time. The third is an association graph whose edges are statistical co-occurrence (PPMI). Recall spreads activation across it with Personalized PageRank. The same quantities drive a "neural" visualisation in which every visual property is a number the system computes. A conversational memory agent lets the user tell their story, and it asks only the questions whose answers reduce its uncertainty most. Those answers become training labels for the gate.

1. The problem in one sentence

Memory fails in two directions: it fills with trivia ("set a 2-minute timer"), or it misses the thing that mattered ("my MLP project deadline is Friday"). One mechanism has to handle both.

Storing everything makes recall noisy and expensive, because every prompt carries irrelevant facts and the model attends to the wrong ones. Storing too little makes the teammates feel like strangers. People solve this with attention and consolidation. Most of a day is never encoded. What surprises us, what we act on, and what we repeat gets stabilised. What we never return to fades. Engram copies that behaviour with explicit, measurable quantities instead of one prompt line that says "skip small talk".

2. Audit of Memory v2

We read mem.py (805 lines), its callers (graph.preamble, tools.recall, calls.context, live.py) and the eval suite, then queried the production tables on 18 October 2026.

662episodes logged (Oct 11–14)
8facts stored (1.2% yield)
2 / 8facts that are test noise
57%of episodes are teammate replies

A low yield isn't wrong in itself. Much of this history is the user testing features ("Hey there", "Start a 2 minute timer"). The problem is what got through and what didn't. Stored: "Saqlain was sent an SMS from Akhil on 2026-10-11 saying: Test from Tubelight, please ignore." Not stored: the user's message "Can u see the deadlines i set for mlp and mlp project?", which names two ongoing courses. The extractor has one instruction about importance and no way to weigh it.

What works and should stay

  • Episodes are append-only. Raw input is never edited, so any later extractor can re-read history. This is the same episode layer Zep uses [3].
  • Verified evidence. The server drops any fact whose quote is not found verbatim in its episode. This is stronger than Mem0's or Zep's published pipelines, and it is the reason poisoning evals pass.
  • Trust levels. The user (2) outranks teammates (1), who outrank outside content (0). Outside content can't set preferences or override better-trusted facts.
  • Bi-temporal facts. valid_from / valid_to plus learned_at. Replaced facts close and corrections retract for good.
  • Evals first. 13 LongMemEval-style cases [9]. v2 scores 18/18 four times in a row; v1 scored 14–15.

3. What others have built, and what we take

The short answer to "do we need to invent a new architecture?" is mostly no. Each piece has a published, tested basis. What's new is how they fit together: a calibrated three-band gate, trained by the user through conversation, sitting on a memory whose evidence is verified.

WorkCore ideaWhat Engram takes
Generative Agents [1]The LLM rates each memory's importance from 1 to 10. Retrieval = recency + importance + relevance. Reflection fires when accumulated importance crosses a threshold.Importance as an explicit field from the extractor. Profiles rebuilt when enough salient change accumulates.

From cognitive science: ACT-R base-level learning [13, 14] gives a strength for each memory from how often and how recently it was used. Its premise is rational analysis: memory strength tracks the probability that a memory will be needed. Synaptic tagging and capture [15] explains how a weak trace survives if something important touches it soon after. That is our tentative tier. Emotional arousal modulates consolidation [16], which matches the "importance" feature. Spreading activation [17] and complementary learning systems [18] (a fast episodic store feeding a slow structured one) frame the whole design.

4. Architecture

4.1 Layers

v2's four layers stay: episodes → entities → facts → profiles. v3 adds three things. Facts gain importance, salience (the gate's p), hits (timestamps of use) and mentions (every entity the sentence names). A new entity kind, period, holds life chapters such as "IITM online degree" or "Building Tubelight". This follows the Self-Memory System model of autobiographical memory [19]: lifetime periods contain general events, which contain specific moments. Edges between entities are not stored. They are computed from mentions, so they can't drift out of sync with the facts.

4.2 Writing: the salience gate

Stage 0 (free, no model). Before any model call, drop episodes that can't hold a lasting fact. That means greetings and acknowledgements with no names, numbers or dates; device commands answered entirely by phone or clock tools (alarms, timers, flashlight); and teammate replies, unless they contain a name, number or date that isn't in the user's turn. This saves extraction quota. It never deletes anything: the episode stays in the log.

Stage 1 (the extractor, same single call as today). For each candidate fact, the model also answers two categorical questions. LLMs are more consistent with a fixed scale than with a free number. Importance: trivial, minor, useful, important or critical (0.1 to 0.9). Durability, how long it will stay true: hours, days, months or years (0 to 1).

Stage 2 (on the server, no model). The server combines those answers with signals it measures itself into one probability that the fact will be needed later:

p=σ(β0+βimpi+βduru+βnovν+βtrτ+βexe+βrepln(1+r))(1)

Here i is importance, u durability, τ trust ÷ 2, e whether the user asked to remember it ("remember this", or anything said to the memory agent), and r how many earlier episodes restated it. ν is novelty, a cheap stand-in for surprise [7, 8, 20]:

ν=1−maxf∈Fscos(e,ef)(2)

Here Fs is what memory already holds about the same subject. A fact that adds nothing has ν near 0. A fact about a new subject has ν = 1.

Where the thresholds come from. If p is calibrated, decision theory gives the threshold directly. Missing an important fact costs more than storing a trivial one. With a miss costing 3× a false keep, the expected cost is minimised by keeping anything above

θlo=cFPcFP+cFN=11+3=0.25(3)

Between 0.25 and θhi = 0.5 (more likely needed than not), a fact is tentative. It is stored but not trusted: it shows up in recall only when strongly matched, it is drawn faintly, and it fades unless something reinforces it. This is the answer to "no tiny details, but nothing big missed". Uncertain items are neither thrown away nor allowed to clutter every prompt.

Fitting β. We start from hand-set priors. We then fit them by logistic regression on labels from three places: hand-labelled real history (§7), the memory agent's questions (§6), and the user's own actions ("that's wrong" and "not important" are labels too). Seven weights need roughly 70–100 labels to fit stably, using the rule of thumb of ten events per variable. The fit runs offline, needs no numpy, and is checked against calibration error (§7) before it ships.

4.3 Tentative memories and consolidation

A tentative fact is like a synaptic tag [15]: a weak trace that something stronger can capture later. When a later episode restates or extends it, r increases in (1), p is recomputed, and the fact may become long-term. When a long-term fact about the same entity arrives within the tag window, the tentative one gets a smaller boost. If its activation (§4.4) falls below the retrieval threshold with no reinforcement, it becomes faded. A faded fact is hidden from recall but never deleted, so the memory agent can still ask about it, and the user can still find it.

v2's profile rebuild becomes salience-triggered, following [1]: an entity's profile is rewritten when the summed salience of its changed facts crosses a threshold, not on every change. Fewer model calls, and better profiles.

4.4 Strength: activation that rises with use and fades with time

Every fact keeps a short list of times it was encoded, restated, or used in a recall a teammate asked for. Its strength is ACT-R's base-level activation [13, 14]:

Bi(t)=ln∑j(t−tj)−d,d=0.5(4)

Time is measured in days, floored at one hour. The decay d = 0.5 is ACT-R's standard value. Anderson and Schooler showed that this power law tracks how likely information is to be needed again in real environments [13]. The chance that a fact can be recalled is then a logistic of activation, with threshold τ and noise s:

Pi=11+e−(Ai−τ)/s,Ai=Bi+γ·logit(pi)(5)

The gate's p acts as a prior: an important fact starts stronger. One guard matters. Facts that appear in a turn's preamble are not counted as uses. If they were, whatever is already strong would be shown more, used more and grow stronger, a rich-get-richer loop. Only explicit recall tool hits and restatements by people count.

Identity facts (a name, a phone number, a relationship) and open commitments never fade, whatever their activation. Forgetting applies to how prominent a fact is, not to whether it's on record.

4.5 Reading: association by spreading activation

Edges. Two entities are linked by how much more often they appear together than chance would predict. This is positive pointwise mutual information over episodes [21], a statistical form of Hebb's rule [22]:

wab=max(0,lnnabNnanb)(6)

One consequence: the user appears in nearly every episode, so their PPMI with everyone is about zero. Mathematically, the user is the context, not a node. The visualisation draws them as the field everything sits in rather than as a hub with a line to everything.

Spreading activation. The entities a moment mentions become seeds s. Activation spreads by Personalized PageRank [6, 23], with W the column-normalised edge weights and restart α = 0.15:

π(k+1)=αs+(1−α)Wπ(k)(7)

Twenty iterations leave an error below 0.8520 ≈ 4%. This is plain Python over a sparse dictionary, which matters because NumPy can't load on the home server's CPU. A question about "the demo" then reaches Priya, who asked for it, and the project it's for, even when neither is named.

Ranking. Each candidate fact gets one score from semantic similarity, the graph mass on the entities it mentions, and its recall probability:

Ri=wssimi+wgmaxa∈mentions(i)πa+waPi(8)

The weights are fitted by grid search on the eval questions, starting from 0.5 / 0.25 / 0.25. This replaces v2's hand-tuned 0.6 / 0.25 / 0.1 / 0.05 blend. The brief is then filled by whole lines in score order until the budget runs out, so nothing is cut mid-sentence.

6. Talking to memory

The memory agent is a chat of its own, by text or voice, where you speak to your memory directly. You tell it about your life, your work and the people around you. It shows what it believes and where that came from, takes corrections, and sometimes asks something. Under the hood:

  • Your words are evidence. Everything you say there is logged as a trust-2 episode with e = 1 in eq. (1): you are deliberately telling it something, which is the strongest signal of importance there is. It still goes through extraction and quote verification. The agent can't invent memories, even when it's the one talking.
  • Tools: recall, a timeline by person or period, why it believes something (the evidence quotes), correct, retract, "not important" (a negative label), merge two people, and propose a fact. A proposed fact is written only after you confirm it.
  • A curiosity queue. It asks the questions it learns the most from. Candidates are tentative facts near the threshold, two current facts that disagree, strongly active people with thin profiles, and open commitments past their due date. Uncertain facts are ranked by uncertainty sampling [29], using binary entropy weighted by importance:
q=H(p)·i,H(p)=−plog2p−(1−p)log2(1−p)(10)

A fact at p = 0.5 is the one the system knows least about, so H = 1 bit. It asks at most two questions per conversation, never in other chats, and never twice within 14 days. A skipped question becomes a weak "not important" label. Each answer is a training example for β, so the gate learns your sense of what matters. This is active learning. It is also what makes the agent feel curious rather than nosy: it only asks where the answer changes something.

Voice works the same way. Gemini Live gets the memory tools, and what you say becomes episodes when the call ends, just as call transcripts already do.

7. How we'll know it works

Write precision and recall
On about 150 real episodes from your history, hand-labelled keep / tentative / skip. Target: no "keep" item skipped (recall ≥ 0.95 on important items) and noise among long-term facts under 10%. v2 today: 25% noise (2 of 8), at least 2 clear misses.
Calibration
Expected calibration error of p against the labels, which must be under 0.1. Without calibration, the thresholds in eq. (3) mean nothing.
Answer accuracy
The existing 13 cases must stay at 18/18. New cases: multi-hop association ("who asked for the thing the demo is about?"), fading (an old trivial fact shouldn't outrank a recent important one), and caller scope (a caller asks about an unrelated private fact and gets nothing).
Cost
Model calls per day must fall: Stage 0 skips most teammate prose. The gate, activation, PPR and layout use no model at all. The curiosity queue needs no model; only the conversation does.

9. Limits

  • Novelty from embeddings is a proxy, not true Bayesian surprise. We can't read the model's own probabilities through a free API.
  • The gate is only as good as its labels. Until there are about 100, it runs on priors and should be read as a sensible default, not as calibrated.
  • PPMI is noisy for rare entities: one co-occurrence between two entities seen once looks strong. We require nab ≥ 2 before drawing an edge.
  • Stress majorization is O(n²) per step. That's fine on a phone up to a few hundred entities. Beyond that, sparse stress [25] or a landmark subset is needed.

Plain-language glossary

Episode
One thing that happened, word for word: a message, a call line, an email a teammate read.
Entity
A person, company, project, place or life chapter that memory knows about.
Fact
One sentence about an entity, with when it was true and the exact words it came from.
Bi-temporal
Two clocks per fact: when it was true in the world, and when we learned it.
Salience gate
The bouncer at memory's door. It estimates how likely you'll need something later.
Tentative
On probation: kept quietly, promoted if it comes up again, faded if it doesn't.
Activation
How "warm" a memory is right now. Use makes it warmer, and time cools it slowly.
PPMI
How much more often two things come up together than chance would predict.
Spreading activation / PPR
Recall that follows associations, the way thinking of one person brings up the project you share.
Stress majorization
A way to place dots so that the distance between them on screen matches how related they are.
Modularity / Louvain
A way to find groups that are more connected inside than to each other: the "regions" of your memory.
Calibration
When the system says 70%, it should be right about 70% of the time.
Active learning
Asking the questions whose answers teach the most, instead of asking everything.
