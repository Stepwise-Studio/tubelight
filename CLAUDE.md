# Tubelight

AI teammates app. Native Expo app (never a web wrapper) + Python agent service + Supabase.
User cares about: token efficiency (don't spawn background agents unless asked), smooth native feel,
no AI slop, Stepwise UI look, squircles, free LLMs only.

## Run (all local; phone = Galaxy S21 FE over USB, adb serial RZCW40ZL54A)
- The desktop app crashes often and kills child processes (even setsid). Run long things as user units:
  `systemd-run --user --unit=tl-svc|tl-metro|tl-release ...` (see git log / previous units; `systemctl --user status tl-*`, `reset-failed` before reuse).
  Keep tool calls short: no sleeps over ~15s, downscale phone screenshots before reading.
- Service: `cd agent-service && setsid .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8787 &` (`kill -USR1 <pid>` dumps stacks).
- Metro: `cd app && setsid npx expo start --dev-client --port 8081 --localhost &`, then `adb reverse tcp:8081 tcp:8081; adb reverse tcp:8787 tcp:8787`. Never start it with `CI=1`: that turns off file watching (edits silently never reach the phone). The phone's USB reconnects drop the `adb reverse` forwards: re-add them when the app sits on "Reloading…".
- Release APK: the laptop has ~4 GB free (the user's other apps); builds get OOM-killed unless capped:
  `systemd-run --user --unit=tl-release --working-directory=$PWD/android -E JAVA_HOME=... -E NODE_OPTIONS=--max-old-space-size=1536 ./gradlew app:assembleRelease -PreactNativeArchitectures=arm64-v8a --no-daemon --max-workers=1 -Dorg.gradle.jvmargs=-Xmx1536m`.
- Models: Gemini 3.5 Flash-Lite is primary (`DEFAULT_MODEL=gemini:gemini-3.5-flash-lite`, 500 free requests a day; fallbacks Groq gpt-oss-120b → Cloudflare gpt-oss-120b → OpenRouter; teammates default to it). 3.8 Flash is opt-in per teammate: its free tier is only 20 requests a day (`gemini-flash-latest` is an alias sharing that quota); `llm._Transport` notes every 429 and `chat_model` skips a model until it resets (`_cool`). Gemini 3 needs thought signatures on past tool calls; `llm._GeminiSignatures` adds Google's documented placeholder. Voice: `app/modules/live-audio` (local Expo module, Android; levels + three voice bands from an FFT (`Spectrum.kt`) every 16 ms) + `src/components/voice/voice-mode.tsx`. The glow (`src/vendor/voice-glow-native/glow.ts`) is one SkSL shader + a numbers-only driver; check shader changes off-device with CanvasKit (node_modules/canvaskit-wasm: compile `source()`, render a frame to PNG) before the phone.
- Replies: `graph._stream` retries a reply that's empty, cut off or stuck repeating itself (`looping`), and `view_for` hides garbled replies already in history. Cloudflare calls send `max_tokens` 4096 and gpt-oss `reasoning_effort` low (its default cap left replies empty).
- Groq free tier = 8k tokens per minute per model: every request (instructions + tools + history) must fit. Composio tool schemas are trimmed (`connectors._lean`), earlier tool results shrink (`graph.shrink_old_results`), Groq history budget `llm.GROQ_HISTORY_BUDGET`; Cloudflare `@cf/openai/gpt-oss-120b` is the overflow fallback. Cloudflare models flagged `require_workers_paid` are hidden and skipped.
- Debug (dev-client) builds: same systemd-run caps as release but `-Dorg.gradle.jvmargs=-Xmx900m` and `-E CMAKE_BUILD_PARALLEL_LEVEL=1` while C++ (CMake) steps must run (after a prebuild or a native C++ change); once those are cached, 900m runs out of heap at dex merging: use `-Xmx1536m` (built in 1.5 min). Check the build once after ~3 min (`vmstat`, last `> Task`), never wait blind: with a 1.4 GB heap the app's CMake step swapped for 20+ min (finished in under 2 min with 900m). Watch `vmstat`: high `wa` + full swap = kill and rerun (finished tasks are cached).
- Native rebuild only after adding native deps: `cd app/android && JAVA_HOME=~/.local/share/jdk/jdk-17* ./gradlew app:assembleDebug -PreactNativeArchitectures=arm64-v8a` (JDK 25 breaks CMake). `android/` is generated (CNG); if missing: `CI=1 npx expo prebuild -p android`, then `echo "sdk.dir=$HOME/Android/Sdk" > android/local.properties`.
- adb: `~/Android/Sdk/platform-tools/adb`. Screenshot: `adb exec-out screencap -p > f.png` (black = phone locked). Deep link: `adb shell am start -a android.intent.action.VIEW -d "tubelight://chat/<threadId>" studio.stepwise.tubelight`.
- Checks before done: `cd app && npx tsc --noEmit && npx expo lint`; `cd agent-service && .venv/bin/pytest -q`.

  Sandboxes (`deploy/server-setup.sh`, idempotent, no sudo): the agent reaches Docker only through `tl-docker-proxy` (containers + exec), sandboxes (`tubelight-sandbox`, lean Node 22 + Python, built on the server from `agent-service/sandbox/`) run as uid 1000 with caps dropped, read-only root, on the internal `tl-sandbox` network whose only exit is `tl-egress-proxy` (squid, `deploy/squid.conf`) refusing private/LAN addresses. Roles get a sandbox by `tools.builder` (free-text role regex). `git_push` only with `GITHUB_TOKEN`. - Public URL `https://tubelight.stepwise.studio` via the existing remote-managed tunnel `snoofy-home` (systemd cloudflared on the server). App `.env` `EXPO_PUBLIC_AGENT_URL` points there. Gradle doesn't see `.env` changes: after editing it, `rm -rf android/app/build/generated/{assets,res}/react` before `assembleRelease`, then verify with `unzip -p <apk> assets/index.android.bundle | strings | grep stepwise`.
- Code-only redeploy (fast, ~20 KB): ship `app/` + `teammates/` as a thin layer: tar a temp dir with
  `Dockerfile` = `FROM tubelight-agent` / `COPY app /srv/app` / `COPY teammates /srv/teammates` (+ `runner`, `sandbox`, `deploy` when they change: the runner downloads them), pipe it to
  `ssh akhil@192.168.0.5 docker build -t tubelight-agent -`, then `bash ~/tubelight/deploy/run-agent.sh`.
  The slim image has no system zoneinfo: `tzdata` (requirements) must stay installed, or every user's time silently becomes UTC (startup logs an error if it's missing).
  NumPy/fastembed can't load on this CPU (no SSE4.2): never switch it back to local embeddings.
  The laptop's local service (`tl-svc`) must stay stopped while the server runs (both would fire schedules).
- Full redeploy (new deps): `cd agent-service && docker build -t tubelight-agent . && docker save tubelight-agent | gzip -1 | ssh akhil@192.168.0.5 docker load` (slow Wi-Fi, ~10 min; run as a systemd user unit), then re-run the container.

## Rules
- Secrets live only in `agent-service/.env`, `app/.env`, `.env.test` (all gitignored). Never print or commit them.
- Commit after each coherent chunk, with the Co-Authored-By line.
- Avatars are static DiceBear Notionists SVGs (`src/ui/avatar.tsx`, cached per seed+colour); `avatar_shape` = `face:<seed>` or a legacy shape name (then the name is the seed). No avatar animation: the user dislikes it.
- `npx expo install <pkg>` only; a new native dep means a dev-client rebuild.
- Reanimated gotcha (release builds only): a view whose resting state is only reached by animating a shared value can snap back to its first-render style on a later React commit. Make the rendered/initial state the resting one (entering/exiting layout animations, offsets that rest at 0); never animate views you've already unmounted. Verify overlay/animation changes on a release APK, not just the dev client.
- Android/Yoga gotcha: a horizontal ScrollView (tables, code) inside a shrink-to-fit container (a chat bubble with `alignItems: flex-start` parents) inflates it to thousands of px. Give such containers a definite width (`hasWideBlock` in message-row).
- UI iteration: use the dev client + Metro (`tl-metro`) with fast refresh instead of release builds; open it via `tubelight://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8081`. Stop Metro before release builds (memory).
- Chat composer floats over the list (absolute inside an in-flow wrapper so it stays above the keyboard; the list pads by its measured height) with no bar behind it: transparent at the top, easing into the canvas colour, and a progressive blur only along the screen's bottom edge (`EdgeBlur` blurs the `BlurTargetView` around the list); the pill (mic inside) widens to full width while focused. @mentions: `lib/mentions.ts` (teammates, `@all`, connected apps as `@<toolkit lowercased>`); mentioned apps travel as `apps` on the message and are lent to whoever answers that request (`RunCtx.scope`).
- Usage (`usage.py`, `/usage` screen from Profile): Groq limits from its headers, OpenRouter `/key`, Composio usage API (100k calls/month free), Cloudflare neurons (needs Account Analytics: Read on CF_API_TOKEN), DB size; Gemini requests are counted by `llm._Transport` per Pacific day (store ns `usage`). Pickers: `ui/radio.tsx` `PickerField` (radio rows in a sheet, search at 8+); tests stub `connectors.ready`/`catalog` (never reach Composio).
- Notifications (`push.py`, app `lib/notifications.ts`, `lib/push-routing.ts`, `components/notify-prefs.tsx`): Android gets data-only FCM messages sent straight through Firebase (`FCM_SERVICE_ACCOUNT_B64`, signed with `cryptography`), which expo-notifications draws itself with action buttons (categories `approval` Approve/Reject, `question` Answer, `reply` Reply; pressed with the app closed they run the `expo-task-manager` background task), the sound channel `tl-<sound>` (wavs in `app/assets/sounds`, one channel per sound) and `tag` = thread (one notification per chat). Expo's push service draws pushes without buttons, so it's only the fallback. Replies are bundled per chat (`BUNDLE_S`), prefs (all/needed/off overall + per chat, sound) in the store. Faces: `/faces/{seed}.png` serves cached DiceBear PNGs (DiceBear stalls from phones); `app/patches/expo-notifications+*.patch` (patch-package) reads `data.image`, and `package.json` `expo.autolinking.android.buildFromSource: ["expo-notifications"]` (SDK 57 ships it precompiled, which would skip the patch).
- Navigation (`components/tab-bar.tsx`): a capsule of three pinned places (AsyncStorage `tl.nav.pinned`) with the old sliding tubeSoft pill; the current place carries a small up/down mark and tapping it again (or long-pressing any) opens every place in a Stepwise dropdown (radius 20, rows 12) grown out of it (scale 0.3→1, 360ms; Edit pins there), mounted only while open with entering/exiting; plus a round New button. The user wants Linear only as inspiration, Stepwise look and feel. Files: `lib/vault.ts` `Viewable` is anything the viewer opens (vault file, chat attachment `/file`, a file another app opened `/open` via `+native-intent.tsx` and `Phone.openFile`); `components/vault/viewer-screen.tsx` + `viewers.tsx`. Google sign-in: `lib/auth.ts` (Supabase OAuth, PKCE, `tubelight://auth`; Profile → Sign-in links Google to the current account); Supabase has Google on, `tubelight://**` allowed and manual linking on (set 2026-10-06).
- Every screen fades and blurs under the bottom edge: `components/bottom-edge.tsx` `EdgeScreen` is the `screenLayout` of the root Stack (skips `(tabs)`, chat, sign-in) and of the Tabs (reaching up under the capsule); chats do it in the composer.
- Full-height sheets (new teammate/project) render in `SheetsHost` above the navigator via `openSheet()`, not as transparent-modal routes (Android's native stack drew the tabs over them).
